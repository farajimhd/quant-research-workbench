# Selected fundamentals v1

The existing normalized reference source, context and fact tables remain the
authority for retained observations. No duplicate ticker-day feature table is
created. `v1.FINANCIAL` is the explicit selected feature catalog. Debt components,
parent earnings and common-shareholder earnings are distinct measures.

Run `scripts/run_fundamentals.py backfill --selected-v1` with the reviewed
population manifest, explicit dates, runtime directory and `--execute`. Planning
without `--execute` is read-only. Production writes are workstation-only.
Historical work uses occupied entity cohorts rather than month/entity Cartesian
products. Existing content-addressed publication headers eliminate completed
observations before insertion. New observations retain exact staged readback,
source-change checks and commit receipts. Existing receipts are never reset.

Forward fill uses the same command with mode `forward-fill` and a separate
runtime directory. The first invocation requires `--since-recorded` with an
aware ISO timestamp. Subsequent runs resume the committed watermark with a
seven-day overlap. Advance the watermark only after every admitted batch passes.
The selected contract and population must match. Sources inserting timestamps
older than this overlap require an explicit earlier watermark or reconciliation
backfill; a timestamp watermark cannot detect arbitrarily backdated writes.
Gateways remain acquisition owners; this command does not download data.

`v1.financial_sql(ciks, cutoff, since=..., known_at=...)` serves selected SEC
consolidated contexts as of an aware timestamp, or changes plus pre-window seeds.
It uses existing qualified originals and retained structured bulk observations.
Originals take priority over bulk within the same accession/context. Bulk filing
dates are conservatively usable after next New York midnight, explicitly a
structured-source availability policy, not original-document certification.
Missing period starts, unsupported units, dimensioned observations and unknown
public clocks are excluded from the public view. Provider rows remain retained;
they are not silently promoted when their units or periods are insufficient.
UBS historical exclusion remains enforced. Subsidiary facts are never summed
into the consolidated parent. Reference snapshots use `reference_sql` with the
recorded clock; settlement/execution dates do not become announcement timestamps.

`coverage_sql` produces compact counts. `gap_sql` lists review candidates for
missing selected fields in existing monetary periods; absence does not prove
that a filing reports the field. These candidates are not permission for blanket
archive extraction. First look in the retained structured alternatives and
completed original outputs; extract only a confirmed reported gap. No new
document qualification campaign is launched by v1.

Bulk normalization stays inside ClickHouse with bounded workers, one query
thread and 2 GiB per worker. `derived` operates only on a small consumer response,
never on a fetched historical dataset. It rejects mixed periods/currencies and
conflicting inputs. The monitor shows stage, active/queued/completed/failed,
new versus reused facts, heartbeat age and provisional measured-cohort ETA.
Normalization completion is distinct from full feature/public-time coverage.
