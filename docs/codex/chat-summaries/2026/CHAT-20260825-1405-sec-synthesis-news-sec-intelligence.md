### Narrative

The chat began with a request to extend the existing News Synthesis and labeling architecture to SEC submissions and XBRL filings. The user first asked for a code-and-document review and an implementation order that deferred a new SEC DeepFM model. Two requirements were clarified before implementation. First, SEC Synthesis had to summarize filing submissions, not merely classify forms or expose raw XBRL. Second, the deterministic synthesis had to be supplied to the manually triggered remote LLM review so the remote model reasoned over a bounded, evidence-preserving filing representation rather than an unstructured filing dump. The user then authorized full implementation and app integration, required SEC material to be presented with the same product quality as News, and emphasized that remote LLM calls must remain manual. A final pre-implementation correction made deterministic forecast eligibility mandatory: every SEC synthesis must independently label whether the filing is eligible for forecast use, regardless of whether an LLM review exists.

The resulting authority deliberately separated three concerns. Deterministic SEC Synthesis owns structural parsing, evidence, issuer scope, narrative disclosures, XBRL transitions, reconciliation, readable summary, semantic direction, quality flags, and product eligibility. Manual remote SEC review owns probabilistic issuer interpretation such as materiality, forecast relevance, fundamental direction, positive and negative implications, guidance change, and risk change. A future learned SEC eligibility model was deferred; no DeepFM substitute was invented. Manual review cannot overwrite deterministic eligibility, and a filing without suitable narrative or comparable XBRL evidence is still synthesized but fails forecast eligibility with explicit blockers.

Commit `3f4bab4c5` implemented the main SEC product. The new `sec_synthesis_v1` engine creates one accession-level document from the SEC envelope, issuer views, filing narrative, and XBRL facts. It preserves exact evidence spans, identifies material disclosures and comparable fundamental transitions, reconciles narrative and numeric evidence, generates a human-readable headline and summary, and persists the versioned result to `q_live.sec_synthesis_v1`. Envelope-only submissions remain represented and deterministically forecast-ineligible rather than disappearing. The engine emits separate eligibility records for forecast trigger, reaction study, issuer history, prior context, and follow-up uses with reasons and blocking flags. Source hash, engine, contract, registry, production, and renderer versions provide restart-safe lineage.

The same commit added a manual-only SEC issuer-review schema and worker. Its prompt is built from the durable SEC Synthesis document, so the LLM receives the structured summary, evidence identifiers, transitions, reconciliation, and deterministic context. The review path validates structured output, persists current and append-only history in `sec_llm_issuer_review_v1` and its history table, records provider/model/cost/latency/status provenance, and remains idempotent by accession, source hash, prompt, and schema. The Text Intelligence service exposes manual admission and status endpoints; no automatic SEC review path was enabled. The model-gateway service catalog and documentation were updated for the new SEC review route.

Backend SEC queries were extended to attach synthesis and review state to All SEC, ticker timelines, and SEC Detail. The frontend initially added synthesis summaries, deterministic direction, forecast/reaction/history eligibility, material disclosures, fundamental transitions, reconciliation, and manual-review results. The intent was News-like parity: tables should communicate meaning before form titles, and detail views should prioritize synthesis over raw filing metadata while retaining source documents and text.

The first integrated version exposed two regressions during user UAT. News synthesis stopped appearing because the live Text Intelligence reconciler gave the newer SEC backlog enough shared capacity to starve current News work; the repair established a longer SEC reconciliation window while interleaving corpus work by recency rather than draining one corpus first. The SEC recency icon was also wired only through a market-screener-specific path, so clicking the icon in Signal Stream or other shared tables could not open the SEC ticker timeline. Commit `8c832bac6` moved the popover to an application-level provider and connected the shared `SecurityIdentityCell` SEC marker to the same dispatch path everywhere. It also propagated SEC counts and synthesis/review presentation through canonical ticker and signal-stream data instead of duplicating page-local logic.

The same incident revealed a Windows service-launch failure. Passing very large encoded commands and launch metadata directly through Windows Terminal produced `0x80070005` while starting Model Gateway. The managed lifecycle was changed to write command and metadata launch specifications under the runtime root and pass bounded file paths to the terminal host. The service manager also began coordinating active dependent restarts. This was a fundamental launcher repair, not a Model Gateway exception. Separately, Vite's websocket proxy emitted `ECONNABORTED` when browser websocket traffic was relayed through the development proxy. Commit `b75e7e906` gave the frontend an explicit backend websocket origin and bypassed Vite for live sockets while retaining ordinary HTTP development proxying.

The user then iterated on the visual semantics using browser annotations. SEC labels were initially plain text and visually ambiguous, the marker guide did not provide filing-category icons comparable to News, and the SEC ticker cards overemphasized filing titles even though form titles rarely explain economic meaning. Commit `18f511fc0` introduced the SEC marker system and guide: distinct symbols for results/fundamentals, current events, capital/financing, corporate transactions, ownership, governance, risk/legal, administrative, and other filings, with independent synthesized, processing, AI-reviewed, and attention states. Commit `68786f7a6` added semantic prediction color whose authority is completed manual review when available and deterministic SEC Synthesis otherwise; the glyph remains meaningful without color. Counts and recency remain separate visual layers.

VCIG manual SEC review then timed out even though admission could have succeeded. The root issue was synchronous ClickHouse admission work competing in shared server pools plus ambiguous client timeouts after work had already entered the queue. Commit `10d068ab3` made admission asynchronous and serialized by an explicit lock, persisted the queued acknowledgement before exposing work to the worker, moved blocking database operations off the event loop, and retained deduplication. The backend no longer consumes the shared synchronous endpoint pool for admission. The UI uses a longer acknowledgement deadline and, after an ambiguous network timeout, polls canonical status before declaring failure; retry remains safe because the service deduplicates the same accession/source contract.

Commit `709aa8b84` redesigned the SEC ticker filing cards around decision value. Each card now leads with filing meaning, deterministic forecast eligibility, direction and source authority, then readable synthesis and support labels. Form type, accession, and source title are demoted to provenance. Direction is spatially distinct from categorical badges, and labels use the application's semantic badge and typography patterns. Clicking the card still opens the full SEC reader.

The user then applied the same critique to News. In ticker popovers, deterministic News Synthesis had been large while manual AI prediction was small and mixed with lower-value metadata. Commit `f42626c14` elevated deterministic and AI predictions into the top comparison area and moved support data beneath them. In News Detail, inconsistent `Pos` versus `Positive`, repeated direction displays, staggered cards, weak typography, and duplicated article evidence made the page difficult to scan. Commit `8d8d2d328` reorganized the page into an explicit three-column interpretation section: deterministic synthesis, manual AI review, and market reaction. It standardized full semantic wording, hierarchy, badges, issuer relevance, implication ranges, events, roles, reaction state, topics, and readable evidence. Direct browser inspection covered the VCIG page at desktop and compact dimensions; the managed TypeScript/Vite production build passed. The generic UI review harness loaded an unrelated chart fallback, so its chart findings were not misrepresented as News Detail validation.

The last functional defect appeared when the user pressed Review from News Detail. The remote job could complete, and pressing Review from the ticker later exposed the prediction, but the already-open detail page did not update. The shared hook optimistically set `queued`, then its first status poll could arrive before the worker's queued row was visible. A transient canonical `not_reviewed` response replaced the optimistic state and disabled further polling. Each rendered surface also owned an isolated local state, so completion from one surface did not invalidate another tab. Commit `204a70214` made accepted review admission a separate local lifecycle that remains pending until a canonical `complete` or `failed` row exists. It preserves queued state across admission lag and publishes a lightweight invalidation across same-page components and browser tabs; each receiver refetches the durable backend result rather than copying browser-local predictions. The managed production build passed, reviewed and unreviewed detail states were inspected, and no extra LLM call was made during validation.

All ten implementation and repair commits were pushed to `origin/main`. Runtime artifacts remained outside the repository. Later work may have evolved these files, so future changes must inspect current contracts rather than replaying the historical patches mechanically.

### Durable decisions

- **Confirmed requirement:** Every accession receives deterministic SEC Synthesis, including envelope-only submissions; absence of usable evidence is represented explicitly rather than dropped.
- **Confirmed requirement:** Deterministic SEC Synthesis independently owns forecast eligibility and related product eligibility. Manual LLM review cannot change that authority.
- **Confirmed requirement:** SEC and News remote LLM calls are manual operator actions. SEC review consumes the persisted synthesis document; no automatic SEC review was enabled.
- **Architectural decision:** Narrative disclosures, XBRL transitions, reconciliation, evidence, synthesis, eligibility, and probabilistic review are separate versioned layers with source hashes and current-plus-history persistence.
- **Architectural decision:** Shared ticker identity/marker components and application-level popover hosts own SEC launch behavior across Signal Stream, tables, and scanner surfaces.
- **Architectural decision:** Prediction color uses completed manual review first and deterministic synthesis as fallback; icon kind, recency, count, synthesis state, and review state remain distinguishable layers.
- **Architectural decision:** Accepted manual-review requests remain pending through persistence lag and synchronize by invalidation; the backend remains the result authority.
- **Rejected approach:** Do not add an unvalidated SEC DeepFM merely to imitate the News stack. Learned SEC eligibility remains deferred.
- **Rejected approach:** Do not use filing title/form type as the primary meaning display, and do not hide direction among categorical badges.
- **Rejected approach:** Do not route live browser websockets through Vite when a direct backend websocket authority is configured.
- **Assumption:** The deterministic V1 filing rules are production logic but were not established in this chat as a statistically certified learned forecasting model.
