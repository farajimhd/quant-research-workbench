### Narrative

This chat began as a large expansion of the News Synthesis forecast-eligibility gold authority. The user explicitly allowed extensive subagent parallelism and wanted the work divided into roughly 5,000-article chunks. The governing objective was not simply to manufacture labels: the expansion had to remain prediction-blind, full-source, identity-aware, issuer-scoped, and suitable for later evaluation of the actual News Synthesis engine. The repository was already operating under a strict separation between laptop source authority and generated runtime data. Consequently, source code and reusable tests belonged in `D:\TradingCodes\quant-research-workbench`, while sampling packets, review outputs, manifests, ledgers, audits, and other generated data belonged only under `D:\TradingML\runtimes`.

The labeling campaign froze 20,000 articles with no overlap against the prior 17,000. Four 5,000-article chunks passed through compact high-recall screening, followed by two independent full-body reviews for selected candidates, blind third-pass adjudication where the first two reviews disagreed, and manual resolution of the final uncertain cases. Reviewers were deliberately constrained to the instructions and their exact assigned packet. They could not inspect prior reviews, answer keys, neighboring packets, manifests that exposed decisions, or other agents' conversational results. This narrow-context rule was important because the resulting labels needed to be genuine independent judgments rather than consensus copied across passes.

The user noticed that some agents were staging review files in or near the code workspace and clarified that generated goal artifacts must never be created in the repository. The workflow was corrected immediately. Agents were instructed to write canonical results directly to the applicable runtime review directory when permitted, otherwise use a unique external staging path, copy to the runtime authority through a controlled write, verify hashes, and delete the staging copy. A final read-only repository audit found no campaign JSONL, CSV, log, cache, review, or staging artifacts under `research/text_intelligence/news_synthesis_v1`; `git status` showed only the intended tracked source modifications at that stage. A separate runtime audit independently verified the final manifests, ledgers, evaluations, row counts, and SHA-256 values.

The completed expansion advanced 9,429 articles and 11,997 issuer units from the compact screen to certified full-source gold. All four chunk manifests were complete. Policy uncertainty, quarantine, missing predictions, and engine failures were zero. The user then asked how to use the larger consolidated authority to improve News Synthesis and requested implementation of an evaluator plus a handoff prompt for another chat. Read-only design work compared the existing audit frameworks, the consolidated row shapes, and the actual `NewsSynthesisEngine.synthesize(source)` boundary. The key discovery was that consolidated labels alone cannot replay every article. Manual gold preserves selected source evidence, full-source gold preserves title/body hashes and selected evidence, and Sol gold preserves source-text hashes and labeling metadata, but none uniformly embeds the complete canonical engine input. Treating evidence quotes as reconstructed source text would have contaminated the evaluation. The evaluator therefore needed an explicit source catalog derived from original runtime source artifacts, exact source-hash verification, and a fail-closed response to missing or conflicting source authority.

The evaluation design also rejected using the existing sealed set for iterative diagnosis. That set is final-only and entirely forecast-eligible, so it cannot measure ineligible detection or specificity. Instead, the 16,642 `model_development_allowed` articles were split deterministically and prediction-blind at whole-article granularity. The resulting frozen split contains 13,341 audit articles and 21,256 issuer units, plus a 3,301-article/4,976-unit development holdout. The 1,502-article/1,805-unit final-only partition was preserved unchanged. The split is complete, disjoint, hash-bound to the consolidated manifest, stratified by authority and label characteristics, and stored only under `D:\TradingML\runtimes\text_intelligence\news_synthesis_v1\gold_certified_news_labels_evaluation_split_v1`.

Implementation added `consolidated_gold_evaluator.py`, its CLI, and focused tests. The CLI supports split creation and validation, source requirements, source-catalog certification, checkpointed inference, evaluation, audit validation, and identical-population comparison. Inference passes provider tickers only from original source metadata; gold tickers enter separately as `evaluation_target_tickers` and cannot alter provider candidate resolution. Every expected article is represented by either a prediction or an explicit engine failure. Checkpoints are bound to the split manifest, gold file, evaluation-target set, source catalog, source-catalog manifest, engine version, and inference code authority. Safe hashed checkpoint filenames prevent source IDs from becoming filesystem paths.

The source-catalog contract was strengthened during review. Catalog rows now contain the exact original `source_record`, a declared adapter schema, the runtime-relative artifact path, and the record's canonical hash. Certification accepts explicitly designated JSON, JSONL, or narrow source directories, recursively inventories their records, rejects duplicates, and proves that every catalog record exists in its declared artifact. The trust boundary remains explicit: the evaluator proves membership and immutability, while the caller must establish that the designated artifacts are the correct upstream source authority. Canonical benchmark records are projected through an allowlist so unrelated or gold-derived nested fields cannot flow into inference. Forecast blind-source rows use a deterministic adapter that preserves title, rendered body, author, provider tickers, channels, tags, timestamp, and `url_domain`. Source timestamp and certified title, body, or source-text hashes are checked before the engine runs.

Evaluation produces article results, issuer-unit results, complete audit documents, extra prediction-unit diagnostics, engine failures, mismatches, and bounded mismatch chunks. Eligibility is scored separately at article and issuer-unit levels. Article eligibility is computed over gold-scoped tickers, because not every contributing authority certifies exhaustive article entity coverage; extra predicted tickers remain coverage diagnostics and only extra eligible predictions trigger review. Sentiment is evaluated independently for gold-eligible units with known positive, negative, neutral, or mixed labels. Ineligible `not_applicable` labels and the small number of explicitly missing eligible sentiments are excluded rather than imputed. The audit reports precision, recall, specificity, F1, balanced accuracy, confusion counts, sentiment accuracy and macro-F1, coverage states, identity failures, extras, engine failures, and per-authority metrics.

Review found and repaired several integrity defects before release. Partition loading now validates the frozen manifest, file hashes, identity hashes, and usage policies on every run, preventing a sealed row from being copied into the audit file. Checkpoint fingerprints include exact gold and evaluation-target hashes. Audit validation opens and verifies every indexed mismatch chunk and requires their ordered union to equal the mismatch population. Comparisons validate both audits, require identical article and issuer-unit identities and unchanged gold, and report fixed and introduced errors. Scoring-time code authority is recorded independently from inference-time authority and includes the evaluator, binary-metric implementation, ticker normalization, and hashing contract. Sentiment is no longer gated by predicted eligibility, title-only sources use the same fallback as the engine, and missing or ambiguous identity remains visible rather than silently becoming an ordinary negative prediction.

### Durable decisions

- Confirmed requirement: generated gold, packets, logs, checkpoints, manifests, metrics, temporary scripts, and audit documents remain under `D:\TradingML\runtimes`, never in the repository.
- Confirmed requirement: blind review agents receive only their instructions and exact assigned packet; they may not inspect prior reviews, answer keys, other packets, or other agents' conclusions.
- Confirmed requirement: engine repairs must model generic identity, language, event, role, temporal, source-lane, or aggregation behavior. Source IDs, tickers, company names, and individual expected outcomes cannot be hard-coded.
- Architectural decision: the consolidated dataset is the normalized label authority, not a complete replay-source corpus. Original source artifacts are required for inference and must pass exact hash checks.
- Architectural decision: gold tickers define scoring scope through `evaluation_target_tickers`; they must not be injected into provider ticker or identity-candidate metadata.
- Architectural decision: preserve three evaluation boundaries: iterative audit, development holdout, and final-only sealed test. Split whole articles, never issuer units.
- Architectural decision: sentiment is scored independently on known, gold-eligible units; eligibility and sentiment also remain available for joint error analysis.
- Architectural decision: extra predicted entities are unscored coverage diagnostics unless the contributing authority certifies exhaustive entity coverage.
- Architectural decision: compare repairs only on identical source, gold, article, and issuer-unit populations, reporting both fixed and newly introduced errors.
- Rejected approach: reconstructing article text from evidence quotes or hashes, because it changes the engine input and leaks label-selected content.
- Rejected approach: using the existing positive-only sealed Sol set for iterative tuning or specificity measurement.
- Rejected approach: broad thresholds, ticker exceptions, phrase exceptions without a general linguistic rule, or cross-issuer fallbacks that improve aggregate metrics while creating unrelated regressions.
- Unresolved uncertainty: source-catalog artifact designation proves record membership but still requires the operator to identify the true upstream runtime authorities correctly.
