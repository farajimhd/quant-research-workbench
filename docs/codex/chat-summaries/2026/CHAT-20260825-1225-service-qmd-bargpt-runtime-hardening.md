### Narrative

The user initially asked for an evidence-led investigation of every service log, with special attention to QMD errors and a BarGPT service that appeared not to work. The first response was diagnostic only. Three bounded workers inspected QMD, BarGPT, and the remaining managed-service fleet while the root agent reviewed current health, process ownership, structured logs, task history, prior chat summaries, and the August 24 QMD memory incident. The investigation preserved earlier requirements: QMD source normalization, app streams, and canonical `q_live.events` persistence must not await optional derivatives or repairs; computation targets remain client-owned leases; development QMD runs use the explicit Laptop role; BarGPT keeps immutable v2 champion and v3 shadow releases with full-prefix causal inference; and lifecycle operations never adopt or stop foreign listeners.

The initial runtime evidence showed that QMD Live was in a new P0 resource incident. It reached roughly 127-128 GiB private memory, produced millions of downstream drops, accumulated tens of millions of repair requests, and fell tens of seconds behind during an active collection window. Windows paging, rather than QMD direct file I/O, explained the disk pressure. The new trigger was not identical to the previously fixed per-bucket repair storm. Three Signal Streams had leased expensive 100 ms and one-second bar, NBBO, and tape-pressure capabilities across the complete Core Scan universe, producing more than 43,000 active requirements. QMD retained large full indicator histories, including nested structures, for that demand. Late-event repair then amplified the pressure because repair execution could begin before compact events were durably queryable. Removing only the three runaway optional Signal Stream leases contained further growth without stopping the feed or canonical persistence while the durable fix was implemented.

BarGPT evidence showed a different failure. Both approved hash-pinned releases had loaded and six valid predictions existed, so checkpoint corruption, tensor incompatibility, and CUDA admission were not the cause. The service had taken more than four hours to reach its first prediction and later disappeared without a recoverable initiating exception. The backend destroyed Watchlist priority by sorting tickers before truncation, historical warm-up repeatedly scanned identity, split, intraday, and 800-day daily sources per ticker, model selections were not carried immutably through all scope paths, and the service kept critical failure state only in memory. Because the shared launcher did not persist stdout, stderr, normalized launch inputs, or exit reason, the exact earlier process termination could not be reconstructed. This observability gap was treated as a product defect rather than hidden as uncertainty.

After the user explicitly authorized a goal to fix every confirmed issue fundamentally and efficiently, implementation proceeded in three coordinated lanes. QMD gained a ranked Core Scan prefilter, per-target and 30,000-unit aggregate admission guards, retained-memory estimates, and rejection-before-replacement so an oversized lease cannot erase a valid existing lease. High-frequency indicator history became compact and bounded while the full current row remains authoritative. Condition arrays that exceed the five inline compact tokens now use an exact overflow sidecar, retaining warning audit visibility without corrupting live derivative behavior. Late repair is coalesced by ticker and session, waits for compact persistence acknowledgment and an idle window, and executes through an independent queue with capacity 512, a 2,048-range global coalescer, concurrency one, and four attempts per second. Full queues or shutdown defer safely to restart-stable `q_live.events` reconciliation. Canonical live writers persist rows only and never run repair SQL. Metrics expose pending, backlog, inflight, oldest age, retries, deferrals, and completions. Legitimate zero-work reconciliation reports `up_to_date`.

BarGPT was rebuilt around truthful bounded admission. Ranked ticker order and stable deduplication are preserved. Immutable model IDs propagate through backend, service, prediction, and chart contracts. Automatic inference always keeps v2 champion on the critical path; v3 shadow runs only through deterministic bounded sampling unless explicitly requested. Scope revisions and retention are stable, origins received before readiness coalesce to the newest causal origin, and warming is a typed retryable state rather than an operational failure. Warm rows enter caches in bounded off-event-loop chunks, keeping `/health` responsive under load. A new external-runtime snapshot contract binds model contract hash, exact QMD active-part revision, condition references, identity intervals, and splits; legacy or mismatched snapshots fail closed. Source revision is checked before and after warm-up so concurrent repair cannot create mixed context. The missing `CALENDAR_VIEWS` import found by the real warm path was fixed and covered by a test that reaches snapshot save.

Live restart testing exposed one more lifecycle defect. Although uvicorn reported application shutdown complete, synchronous ClickHouse warm workers launched through `asyncio.to_thread` continued after task cancellation, forcing the service host to exceed its 30-second graceful-stop budget. BarGPT now signals a thread-safe stop event between its bounded ClickHouse requests and has a 45-second managed grace. With four warm workers active on the configured 500-ticker scope, a second live restart stopped cleanly in approximately 28 seconds without force termination.

The shared manager now evaluates semantic readiness rather than treating HTTP 200 or an open port as success. QMD readiness checks required lanes, queue saturation, active degradation, and live event freshness. BarGPT `warming` is a valid visible state, not `ready` and not failure. IBKR requires its supervisor thread, gateway, authentication, keepalive, and ClickHouse states. Per-run external runtime directories persist `run.json`, stdout, stderr, and `exit.json`, with bounded retention. Ownership records include normalized launch inputs and fingerprint components; dead records are archived, generated caches no longer cause false source drift, and operators can see whether launch, environment, host role, source, or artifact changed.

During the production BarGPT canary, TSSI failed point-in-time identity because the provider event timeline ended with synthetic ticker `S258`. Current FIGI, share-class FIGI, CIK, exchange evidence, and the issuer's SEC filing confirmed TSSI. A narrowly signature-bound correction was added and the targeted Reference Gateway reconciliation wrote two events and one interval. Exact audits then reported zero current-ticker mismatch, ambiguity, gap, orphan, or overlap, and TSSI completed its first authoritative warm.

Final fleet rollout was intentionally isolated rather than a disruptive all-service restart. QMD, BarGPT, backend, frontend, IBKR, News, and SEC were restarted only when their owned or shared code required it. SEC's long bind delay was its configured fail-closed ClickHouse and coverage audit. A later Windows `ConnectionResetError(10054, ... forcibly closed ...)` revealed that the shared classifier recognized only the spaced phrase `connection reset`; it incorrectly escalated the retryable provider failure to operator action. The classifier now recognizes Windows exception representations and exposes transient work as `retrying`/`CATCHING_UP` until a later success resolves it. News uses the same corrected contract.

The user then reported two chart defects: session VWAP changed when the chart timeframe changed, and timeframe transitions did not load seamlessly. Direct API evidence confirmed different VWAP values across intraday resolutions. The cause was semantic, not cosmetic: QMD accumulated each selected timeframe's HLC3 multiplied by volume, so changing the bar boundaries changed the benchmark. QMD bars already preserve exact eligible-trade interval VWAP and volume; recombining `interval VWAP x volume` and volume is associative. Commit `a3972aab` therefore changed the shared indicator engine to accumulate exact eligible-trade notional, advanced the calculation revision to `qmd-indicators-v21`, and advanced QMD History's derived cache revision to v29 so stale HLC3 results cannot survive. A regression test proves that fine and coarse aggregation produce the same anchored value at the same causal cutoff.

Chart latency had two independent causes. Five-minute first paint expanded the raw compact-event scan to four hours and took approximately 44.9 seconds in a representative AAPL request, even though a two-hour page already supplies 24 bars and the existing cursor can fetch earlier history. The backend now caps first paint at two hours without truncating authoritative history. In the frontend hook, an uncached timeframe change immediately replaced the chart with empty arrays. The hook now retains the previous complete timeframe while the new request is in flight, ignores premature indicator or empty live snapshots, and atomically replaces bars, indicators, signals, and structure when the first authoritative new-timeframe bars arrive. Symbol, session, and projection changes still clear rather than showing mismatched data. All 172 QMD core tests, all 54 QMD History tests, 35 backend tests plus four subtests, the managed 1,905-module frontend production build, and diff checks passed. The commit was pushed to `origin/main`.

The reported Vite `write ECONNABORTED` websocket-proxy stack was also reconciled with lifecycle evidence. It occurred when the backend side of an active proxied websocket was torn down during managed restart, so Vite reported the transport abort. It was not evidence of a separate VWAP or frontend-state calculation defect. The browser clients reconnect and the hardened manager now exposes semantic backend readiness and durable exit evidence; suppressing the proxy stack would have hidden the causal service transition. A recurring abort while backend ownership and health remain stable would be a new incident and must be correlated with the backend run log.

### Durable decisions

- QMD source normalization, app publication, and canonical persistence have priority over every derivative or repair path. Optional work must be bounded, nonblocking, measurable, and restart-recoverable.
- Computation demand is admitted by explicit client leases under per-target and aggregate budgets. Increasing queues or tolerances is not an acceptable substitute for bounding authority.
- Complete compact-event condition semantics must be preserved. Overflow is audited and stored exactly; it is never silently truncated or ignored.
- BarGPT release identity is immutable end to end. V2 remains champion and v3 remains shadow until fixed-panel evidence authorizes promotion.
- Full-prefix inference remains authoritative until a separate KV-cache parity certification covers masks, rollovers, sessions, splits, corrections, and as-of fusion.
- Warm snapshots are optimizations bound to exact source and model revisions, never a second data authority.
- Session VWAP is exact eligible-trade notional divided by eligible volume and must be invariant across intraday timeframes at the same causal cutoff. Timeframe-specific HLC3 recomputation is rejected.
- A timeframe transition may retain the last complete chart only within the same ticker, session, and indicator projection; the first authoritative replacement page swaps the dataset atomically.
- `warming`, `retrying`, `degraded`, and `ready` are distinct operational states. Port-open and HTTP 200 alone do not establish readiness.
- Managed lifecycle preserves foreign listeners, uses graceful shutdown first, records every run externally, and restarts only affected services.
- The TSSI correction is valid only for its exact FIGI/CIK/provider-event signature; broader identity conflicts remain fail closed.
